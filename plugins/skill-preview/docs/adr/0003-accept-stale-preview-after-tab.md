# 0003 Tab で確定してから送信するまで、右ペインが確定前の候補のままになることを受け入れる

- 状態: 決定（2026-11-04）

## 背景

入力欄に `/gri` と打って候補を Tab で確定したあとも、右ペインに `/gri` で引いた候補が出たままになる、という指摘があった。

Claude Desktop の Code タブ（内蔵の Claude Code 2.1.309）で、入力欄まわりのイベントを書き出して確かめたところ、次のことが分かった。

- 1文字ずつの入力は `prompt.edit` で届く（`/`、`/g`、`/gr`、`/gri`）
- Tab で `/grill-with-docs` に確定したときは、`prompt.edit` も `prompt.change` も届かない
- Enter で送信したときに、`prompt.submit` で確定後の文字列（`/grill-with-docs`）が初めて届く。入力欄が空になったことを知らせる `prompt.change` も届かない

mod 側の入力欄は `/gri` のままなので、`$.prompt.read()` で読み直しても確定後の文字列は分からない。

## 決定

- `prompt.submit` でも入力中のプレビューを閉じる。送ったのがスキルなら、閉じる前に `skill.prompt` で「▶ 実行中」に切り替わる
- Tab で確定してから送信するまでの間、右ペインが確定前の候補のままになることは制限として受け入れ、README に書く

## 理由

- 確定を知らせるイベントが無く、mod の側で確定を知る手段が無い
- 入力が止まってから時間で表示を薄くするといった工夫は、確定したかどうかを区別できず、打ちかけのときにも効いてしまう

## 影響

- README の「制限」に書く
- Desktop が確定を知らせるようになれば、その時点で見直す
