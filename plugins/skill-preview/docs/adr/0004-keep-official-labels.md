# 0004 Desktop の公式訳をアプリの内部ファイルから読む仕組みを残す

- 状態: 決定（2026-11-04）

## 背景

Claude Desktop アプリは、組み込みコマンドのうち 42 件（`/btw`、`/model`、`/help` など）に自前の日本語訳（公式訳）を持ち、候補リストのツールチップに出す。skill-preview は、公式訳をリポジトリに同梱せず、使う人のマシンにあるアプリの内部ファイル（`/Applications/Claude.app/Contents/Resources/ion-dist.asar`）から実行時に読み取り、右ペインで自前訳より優先して出している。

`/model` でツールチップ（公式訳）と右ペイン（自前訳）の文言が違う、という指摘があり、それを受けて作った仕組みである。

[0001](0001-translate-in-pane-only.md) で日本語訳を右ペインだけに出すことにしたため、公式訳の役目は「公式訳のある 42 件で、ツールチップと右ペインの文言をそろえる」ことだけになった。一方で次のコストがある。

- アプリの更新ごとに、約 190 MB の内部ファイルを `od`・`head`・`grep` で読む（約 15 秒。起動の裏で行い、結果は `$.store` にキャッシュする）
- アプリの更新で内部ファイルの形式が変わると読めなくなる
- 約 120 行のコードとテスト

## 決定

公式訳を読む仕組みを残す。候補リストの説明を引き直す処理は、候補リストを書き換えなくなったので外す。

## 理由

- 指摘されたずれ（`/model`）は、まさに公式訳のある 42 件で起きていた
- 読めないときは自前訳に戻るので、壊れても表示が英語になったり止まったりはしない
- すでに作ってテストもある

## 影響

- アプリの内部ファイルの形式に依存する。読めなくなったら自前訳で表示する
- 公式訳の文体は統一されていない（「〜を管理」「〜を進めます」など）が、手を加えずに出す。訳文の文体ルールは自前訳だけに適用する
